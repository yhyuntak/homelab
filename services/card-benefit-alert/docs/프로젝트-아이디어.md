# 카드 혜택 알림 앱 (Card Benefit Alert)

## 📝 프로젝트 개요

위치 기반으로 내가 가진 카드의 혜택을 실시간으로 알려주는 모바일 앱

---

## 🎯 해결하려는 문제

### 현재 상황
- 여러 개의 카드를 소지하고 있지만, 어디서 어떤 카드를 써야 혜택을 받는지 모름
- 카드 혜택 정보를 일일이 외울 수 없음
- 결제 후에야 다른 카드를 쓸 걸 후회하는 경우 많음

### 사용자 니즈
> "어디 건물이나 식당을 가면, GPS로 위치를 감지해서 내가 가진 카드 중에서 어떤 혜택을 받을 수 있는지 알림으로 알려주면 좋겠다"

---

## 💡 솔루션

### 핵심 기능

#### 1. 실시간 위치 기반 알림
```
[GPS 감지] → 스타벅스 입장
→ 알림: "신한카드로 결제 시 30% 할인!"
```

#### 2. 지도에서 미리 확인
```
[카카오맵/네이버맵 열기] → 주변 음식점 표시
→ 🔵 이 카페: KB카드 2000원 할인
→ 🟢 저 식당: 현대카드 10% 할인
```

---

## 🔍 시장 조사

### 기존 앱들의 한계

| 앱 | 주요 기능 | 한계점 |
|-----|----------|--------|
| **뱅크샐러드** | 소비패턴 기반 카드 추천, 자동 가계부 | ❌ 위치 기반 실시간 알림 없음 |
| **캐시노트** | 사장님용 매출 관리 | 타겟 사용자가 다름 |
| **토스** | 자체 카드 혜택 정보 | 한정적 |

### 우리의 차별점

```
기존 앱:  "어떤 카드가 좋은가?" (정적 추천)
우리 앱:  "지금 여기서 어떤 카드 쓸까?" (실시간 위치 기반)
```

---

## 🛠 기술적 구조

### 필요한 데이터

#### 1. 카드 혜택 정보
```
- 카드명
- 가맹점/브랜드
- 혜택 내용 (할인율, 할인액, 적립률)
- 조건 (월 사용 한도, 횟수 제한 등)
- 유효 기간
```

#### 2. 가맹점 위치 정보
```
- 브랜드명 (예: 스타벅스)
- 개별 매장 위치 (위도/경도)
- 카카오맵/네이버맵 POI 데이터 활용
```

### 데이터 수집 방법

#### ⚠️ 카드사 API 현황
- **나쁜 소식**: 카드사들이 가맹점 혜택 정보를 공개 API로 제공하지 않음
- **MyData API**: 개인 사용내역/포인트 조회만 가능 (혜택 정보 X)
- **일부 카드사**: 신한 DataBada, KB API Portal (파트너십 필요, 개인 접근 어려움)

#### 💡 대안 방법

**Option A: 수동 입력 (MVP 추천)**
```
장점:
- 법적 리스크 거의 없음
- 빠르게 시작 가능
- 공개된 정보를 재정리하는 것은 합법

단점:
- 초기 데이터 구축에 시간 필요
- 주기적 업데이트 필요
```

**Option B: 크롤링 (주의 필요)**
```
장점:
- 자동화 가능
- 대량 데이터 수집

단점:
- 이용약관 위반 가능성
- 법적 리스크 존재
- 서버 부하 문제
```

**Option C: 커뮤니티 기반**
```
초기: 수동 입력
성장: 사용자들이 혜택 정보 제보
```

**Option D: 카드사 파트너십 (장기)**
```
트래픽 생기면 → 카드사 컨택 → 공식 데이터 제공
(뱅크샐러드, 카드고릴라 방식)
```

## 🚀 MVP 계획

### Phase 1: Scrappy MVP (1-2주)

**목표**: 개념 검증 (Proof of Concept)

**범위:**
```
1. 인기 카드 5개만
   - 신한 딥드림
   - 현대 M포인트
   - 삼성 탭탭오
   - KB 국민카드
   - 카카오뱅크 체크카드

2. 가맹점 카테고리 3개
   - 카페 (스타벅스, 이디야, 투썸)
   - 편의점 (GS25, CU, 세븐일레븐)
   - 주유소 (SK, GS칼텍스, 현대오일뱅크)

3. 혜택 정보 수동 입력
   - 각 카드사 홈페이지에서 직접 확인
   - DB에 직접 입력 (1-2시간)

4. 간단한 지도 앱
   - 카카오맵 API 사용
   - 내 위치 100m 반경 가맹점 표시
   - 클릭하면 혜택 정보 팝업
```

**핵심 검증 포인트:**
- ✅ 사람들이 실제로 쓸까?
- ✅ 위치 기반 알림이 유용한가?
- ✅ 데이터 업데이트 주기는 얼마나 필요한가?

### Phase 2: 확장 (필요하면)

```
- 더 많은 카드 추가 (10-20개)
- 더 많은 가맹점 카테고리
- 푸시 알림 추가
- 사용자 맞춤 설정 (보유 카드 등록)
- 데이터 자동화 고려
```

### Phase 3: 성장

```
- 크롤링 자동화 (법률 자문 후)
- 카드사 파트너십
- 수익 모델 구축
```

## 💻 기술 스택 (제안)

### Option A: 모바일 앱 우선
```
Frontend:  Flutter / React Native
Backend:   Node.js / Python (FastAPI)
Database:  PostgreSQL + PostGIS (위치 데이터)
Map:       카카오맵 API / 네이버맵 API
Push:      Firebase Cloud Messaging
```

### Option B: 웹앱 먼저
```
Frontend:  React + 카카오맵 API
Backend:   Node.js / Python
Database:  PostgreSQL
Deploy:    Vercel / Netlify (Frontend)
           Railway / Fly.io (Backend)
```

## 📊 데이터 구조 (예시)

### Cards (카드)
```typescript
{
  id: string
  name: string           // "신한 딥드림"
  issuer: string         // "신한카드"
  image_url: string
  annual_fee: number
}
```

### Benefits (혜택)
```typescript
{
  id: string
  card_id: string
  merchant_type: string  // "스타벅스" | "GS25" | ...
  discount_type: string  // "percent" | "amount" | "point"
  discount_value: number // 30 (%) | 2000 (원)
  condition: string      // "월 3회 한도"
  valid_from: date
  valid_until: date
}
```

### Merchants (가맹점)
```typescript
{
  id: string
  brand: string          // "스타벅스"
  name: string           // "스타벅스 강남역점"
  latitude: number
  longitude: number
  category: string       // "카페"
}
```

## 🤔 고려사항

### 1. 가맹점 매핑 문제
```
카드사 혜택: "스타벅스 전체 30% 할인" (브랜드 단위)
              ↓
실제 앱:     개별 매장 위치 필요 (위도/경도)
              ↓
해결:        카카오맵 API로 브랜드명 검색 → 매장 위치 매핑
```

### 2. 데이터 신선도
```
문제: 카드 혜택은 매달 바뀜
해결:
  - Phase 1: 수동 업데이트 (월 1회)
  - Phase 2: 사용자 제보 시스템
  - Phase 3: 크롤링 자동화
```

### 3. 법적 이슈
- 공개된 사실 정보 수집은 합법
- 카드사 문구 그대로 복사는 저작권 위반
- 자세한 내용은 `법적-자문-가이드.md` 참고
