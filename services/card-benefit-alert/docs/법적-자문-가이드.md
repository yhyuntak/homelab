## 법적 이슈 개요

### 핵심 질문

```
Q1. 카드사 홈페이지에서 혜택 정보를 수집해도 되나?
Q2. 크롤링과 수동 입력의 법적 차이는?
Q3. 얼마나 수집해도 괜찮은가?
```

### 관련 법률

1. **저작권법** - 데이터베이스 제작자의 권리
2. **정보통신망법** - 정보통신망 침해
3. **형법** - 컴퓨터등장애업무방해
4. **부정경쟁방지법** - 타인의 성과 무단 사용

## 크롤링 vs 수동 입력

### 🤖 크롤링 (자동 수집)

#### 법적 리스크

| 법률 | 위반 가능성 | 설명 |
|------|-----------|------|
| **이용약관** | 🔴 높음 | 대부분 카드사가 크롤링 금지 명시 |
| **저작권법** | 🟡 중간 | "상당한 부분" 복제 시 위반 |
| **정보통신망법** | 🟡 중간 | 허용된 접근 권한 초과 시 |
| **업무방해죄** | 🟡 중간 | 서버에 과부하 발생 시 |

#### 판례: 여기어때 vs 야놀자 (2022)

```
결과: 무죄 (대법원 확정)

이유:
- 공개된 정보 크롤링
- 일반 이용자에게도 공개된 정보
- 허용된 접근 권한을 넘지 않음

⚠️ 주의: 여전히 법적 불확실성 존재
```

#### robots.txt

```
- 법적 구속력: ❌ 없음 (권고안일 뿐)
- 윤리적 의무: ✅ 지켜야 함
- 위반 시: 이용약관 위반으로 간주 가능
```

### ✍️ 수동 입력

#### 법적 리스크

| 방식 | 법적 리스크 | 이유 |
|------|-----------|------|
| **소량 수동 입력** | 🟢 낮음 | 개인적 정리, 공개 정보 활용 |
| **대량 수동 입력** | 🟡 중간 | "상당한 부분" 복제로 볼 여지 |

#### 왜 수동 입력이 안전한가?

**1. 공개된 정보**
```
카드사 홈페이지 = 누구나 볼 수 있는 공개 정보
사람이 보고 메모 = 당연한 권리
```

**2. 사실 정보는 저작권 보호 대상 아님**
```
✅ "스타벅스에서 30% 할인" = 사실 정보
   → 누구나 수집/정리 가능

❌ 신한카드가 쓴 마케팅 문구 = 저작물
   → 그대로 복사하면 안 됨
```

**3. 재정리/재구성 = 새로운 DB**
```
신한카드 DB: 카드별 → 혜택 나열
내 DB:       위치별 → 카드 추천
            (다른 구조, 다른 가치)
```

---

### 📊 실전 비교

```
❌ 위험한 방법
# 신한카드 전체 혜택 페이지 자동 크롤링
for page in range(1, 1000):
    scrape_all_benefits(page)

⚠️ 애매한 방법
# 적은 양이지만 자동화
scrape_top_10_cards()

✅ 안전한 방법 (MVP)
# 사람이 직접 홈페이지 보고 입력
신한 딥드림: 스타벅스 30% 할인 (월 3회)
현대 M포인트: GS25 2천원 할인
KB 국민카드: 편의점 5% 할인
```

---

### 💡 안전한 수집 가이드라인

#### ✅ DO (해도 되는 것)

```
1. 공개된 사실 정보 수집
   - 카드명, 할인율, 가맹점명

2. 내 방식으로 재구성
   신한카드: "스타벅스에서 특별한 순간을..."
   내 DB:    "스타벅스 | 30% | 월 3회"

3. 선택적 수집
   - 신한카드 1000개 혜택 중
   - 인기 혜택 10개만 선택 = 편집 저작권

4. 부가가치 추가
   - GPS 기반 알림 ← 새로운 기능
   - 지도에 표시    ← 차별화
```

#### ❌ DON'T (하지 말아야 할 것)

```
1. 카드사 문구 그대로 복사
   ❌ "스타벅스에서 특별한 순간을 30% 할인으로 즐기세요"

2. 전체 DB 통째로 복사
   ❌ 신한카드 전체 혜택 1000개 전부

3. 자동화된 대량 수집 (초기에는)
   ❌ 크롤링 봇 돌리기
```

## 💡 법적으로 안전한 MVP 전략

### Phase 1: 완전 안전 (지금 당장)

```
✅ 인기 카드 5-10개만
✅ 각 카드당 혜택 3-5개만
✅ 직접 손으로 타이핑
✅ 카드사 표현 변형

예시:
카드사: "스타벅스에서 특별한 순간을 30% 할인으로..."
내 DB: "스타벅스 | 30% 할인 | 월 3회 한도"

총 작업시간: 1-2시간
법적 리스크: 거의 0%
```

### Phase 2: 성장 (사용자 생기면)

```
옵션 A: 커뮤니티 기반
- 사용자들이 혜택 정보 제보
- 크라우드소싱

옵션 B: 계속 수동 (안전)
- 데이터팀 운영
- 주기적 업데이트

옵션 C: 법률 자문 후 자동화
- 변호사 의견 받고
- 조심스럽게 크롤링
```

### Phase 3: 사업화 (트래픽 생기면)

```
✅ 카드사 파트너십
- 트래픽을 무기로 카드사 컨택
- 공식 데이터 제공 받기
- (뱅크샐러드, 카드고릴라 방식)
```

## 🎯 핵심 정리

### 법적으로 안전한 방법

```
✅ 공개된 사실 정보 수집
✅ 내 방식으로 재정리
✅ 부가가치 추가 (GPS 알림 등)
✅ 소량부터 시작
✅ 카드사 문구 그대로 복사 X
```

### 리스크가 있는 방법

```
❌ 자동 크롤링 (이용약관 위반)
❌ 대량 DB 통째로 복사
❌ 카드사 마케팅 문구 그대로 사용
❌ 법률 자문 없이 사업화
```

### 권장 순서

```
1. 한국저작권위원회 전화 (무료, 10분)
   ↓
2. 로톡 온라인 질문 (무료)
   ↓
3. MVP 시작 (수동 입력)
   ↓
4. 필요시 로톡 유료 상담 (3만원)
   ↓
5. 사업화 단계에서 스타트업 법률지원 (무료)
```
